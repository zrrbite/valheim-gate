# Hooks report: an always-on engine for every way (Valheim 1.0.17)

Sources: `av.il` (the game's IL, line numbers below are lines in that file) and the mod on `feature/run-mode`.
Nothing was edited. "Sure" means read directly in the IL or the code. "Likely" means inferred, with the reason given.

One finding cuts across sections 1, 2, 3 and 5. **`StatusEffect` exposes public virtual hooks that SEMan calls on
every character.** They are `OnDamaged(HitData, Character)`, `ModifyAttack(SkillType, ref HitData)`,
`ModifyBlockStaminaUsage(float, ref float)`, `ModifyTimedBlockBonus(ref float)`, `ModifySwimStaminaUsage(...)` and others
(StatusEffect class at 103014-103957). `SEMan.AddStatusEffect(StatusEffect, ...)` MemberwiseClones whatever instance it is
handed and never consults ObjectDB (95615). The mod already relies on that for `SE_Stats` and `StatusEffect` instances
(HunterHush, BoonEffects.cs:3530; SagaWinds.cs:85). So a **mod-defined subclass** (`class SagaEngineSE : SE_Stats { overrides }`)
made with `ScriptableObject.CreateInstance<T>()` gets per-hit callbacks without a Patcher change. No such subclass exists in
the mod yet (grep for `: SE_` / `: StatusEffect` finds none). Unity accepting a ScriptableObject type from this
runtime-loaded assembly is *likely*, not proven: the mod already `AddComponent`s its own MonoBehaviours (CheatController,
UIManager), and BepInEx mods routinely subclass StatusEffect. Confirm with a first-launch log line.

## 1. Landed hits by the local player (Berserker's Fury), and the damage of a hit

**Where EnemyHits (=5) is incremented.** There is exactly one site with constant 5: `Character.RPC_Damage(long, HitData)`
(8103), at IL_0009-IL_0039, the very top of the method:

```
if (hit.GetAttacker() == Player.m_localPlayer)
    Game.instance.IncrementPlayerStat(IsPlayer() ? PlayerHits(8) : EnemyHits(5), 1f, false);
    m_localPlayerHasHit = true;            // private bool, line 1594
```

- `Game.IncrementPlayerStat` (355329) calls `PlayerProfile.IncrementStat` (375168), which always writes
  `m_playerStats[0].m_stats` (via `Utils.IncrementOrSet`). Sure.
- **Which client.** `Character.Damage` (just above 8103) calls `ZNetView.InvokeRPC("RPC_Damage", hit)`, and that routes to
  `m_zdo.GetOwner()` (296551). So the stat ticks on the **victim's owner**, and only when that client's local player is
  the attacker. Solo, or for creatures the player owns (the normal case near the player), it is the local player's client.
  When the owner is local, `ZRoutedRpc` dispatches synchronously through HandleRoutedRPC. In multiplayer, a creature owned
  by another peer is counted by nobody. Sure.
- **What it counts.** It counts every hit DELIVERED to a non-player Character, before the dodge, IsDead, block and
  resistance checks. Zero-damage, blocked and dodge-invincible hits all count.
  - Each target of a sweep or area attack counts separately. `Attack.DoMeleeAttack` (77278) calls
    `IDestructible.Damage` once per target inside its hit loop (IL_0a1f), and the `<DoAreaAttack>g__checkHits`
    method (80189), `Aoe.DoDamage` (442303) and `Projectile.OnHit` (73358) do the same per target. Arrows count
    when they land. Sure.
  - It does **not** count DoT ticks. SE_Burning and SE_Poison call `ApplyDamage` directly (97200 area), not RPC_Damage.
  - It does **not** count ballista bolts, whose attacker is null (see section 4).
  - **Caveat: it DOES count the mod's own HitData abilities.** Rend, Thor's Wrath, the Ward and Shield Bash all
    `SetAttacker(player)` and go through `Character.Damage`, so each target struck by an ability adds a "hit". If Fury
    should count weapon hits only, either subtract the mod's own hits (`DamageOne` and `SeaWatch.StrikeOne` know how
    many they issued) or use the attacker-side hook below.

**How the mod reads stats today.** `RunService.ReadPlayerStat(string)` (RunService.cs:6645) reads
`Game.instance.GetPlayerProfile().m_playerStats[0].m_stats.TryGetValue(type, ...)`, and `ResolveStatType` (6675) parses
the name. `ReadPlayerStat("EnemyHits")` already works. Polling the delta every frame or poll tick is enough: the write is
synchronous, so nothing is lost between polls, they are summed.

**Attacker-side alternative (per hit, sees the outgoing damage).** `SEMan.ModifyAttack(SkillType, ref HitData)` (96454)
loops every SE and calls the virtual `StatusEffect.ModifyAttack`. It is called by:
- `DoMeleeAttack` IL_09e8, per target, after the target passes the friendly check and just before Damage at IL_0a1f.
  `hit.m_hitCollider` is set (IL_092e), so the target is `m_hitCollider.GetComponentInParent<Character>()`.
- `DoAreaAttack.checkHits` (80018), per target.
- `FireProjectileBurst` (76576), once per volley **at launch, not on landing**.

So a custom SE on the player that overrides `ModifyAttack` counts melee and area hits exactly (attacker-side and
synchronous) and sees the **pre-resistance** damage. It sees nothing of arrows landing, and it fires even if the target
then dodges or blocks.

**Damage actually dealt.** `Character.m_onDamaged` is `public Action<float, Character>` (line 1306). It is invoked at the
end of `Character.ApplyDamage(HitData, bool, bool, DamageModifier)` (8835), IL_028c-IL_02a1, as
`m_onDamaged(totalDamage, hit.GetAttacker())`:
- `totalDamage` is V_1, taken after the difficulty and player-damage-rate modifiers, resistances, and armour
  (RPC_Damage applies resistance and armour before calling ApplyDamage, IL_058d-IL_05cd). It is direct damage only:
  fire, spirit and poison are zeroed off the hit at IL_05d2-IL_0624 and become DoTs. Frost and lightning stay in.
- It is skipped when damage <= 0.1 (IL_0099-IL_00ce).
- Like RPC_Damage, it runs on the victim's owner.
- DoT ticks also arrive through ApplyDamage, with a null attacker (SE_Burning builds the HitData with no attacker).
- BaseAI subscribes the same way: `m_character.m_onDamaged += OnDamaged` in BaseAI.Awake (85547). The mod already
  subscribes on the player (CheatCommands.cs:1247, CombatService.cs:248).

For "heal 10% of damage dealt", subscribe a handler on nearby non-player Characters from the poll. Use `-=` then `+=` so a
repeat subscribe is idempotent. Filter `attacker == Player.m_localPlayer` and heal `0.1f * damage`.

Two other per-hit mechanisms exist, neither a percentage:
- `Attack.m_attackHealthReturnHit`: a flat heal per hit (DoMeleeAttack IL_0a24-IL_0a54).
- `Character.AddAdrenaline`: per hit, IL_0abc.

**Verdict: poll `m_playerStats[0].m_stats[EnemyHits]` (existing ReadPlayerStat) for hits; existing hook
`Character.m_onDamaged` (subscribe per nearby creature) for damage dealt; no Patcher change.**

## 2. Blocks and parries by the local player (Húskarl's Guard)

`Humanoid.BlockAttack(HitData hit, Character attacker)` (28243-28731) is called from `Character.RPC_Damage` IL_042f, on
the victim's owner, so on the local player's client for the player. It runs only `if (hit.m_blockable && IsBlocking())`.
What it does:

1. **Facing.** It returns false if `Vector3.Dot(hit.m_dir, transform.forward) > 0`, a hit from behind (IL_0000-IL_001e).
2. **Blocker.** `GetCurrentBlocker()`; null returns false.
3. **Parry.** `isParry = blocker.m_shared.m_timedBlockBonus > 1 && m_blockTimer != -1 && m_blockTimer < 0.25`
   (IL_002b-IL_005d). `m_blockTimer` is a private float (22602): 0 when the guard goes up, increases while blocking, and
   -1 when not blocking (UpdateBlock, 28792). `m_perfectBlockInterval = 0.25` is a const (22603).
4. **Block power.** `blockPower = blocker.GetBlockPower(GetSkillFactor(Blocking))`. On a parry it is multiplied by
   `m_timedBlockBonus`, and **`SEMan.ModifyTimedBlockBonus(ref blockPower)` is called (IL_0087)**. That call site is unique
   in the game: it fires only on a parry attempt.
5. **Blocked amount.** `blocked = GetTotalBlockableDamage() - after ApplyArmor(blockPower)` (V_7), and
   `fraction = Clamp01(blocked / blockPower)` (V_8).
6. **Stamina.**
   - The cost is `parry ? m_perfectBlockStaminaDrain : m_blockStaminaDrain * fraction`, then
     `+= cost * GetEquipmentBlockStaminaModifier()`.
   - **`SEMan.ModifyBlockStaminaUsage(cost, ref cost, false)` is called at IL_012a.** A positive cost is spent with
     `UseStamina(cost)`; otherwise `AddStamina(-cost)` (IL_010f-IL_014b).
   - `Humanoid.m_blockStaminaDrain` is public; its constructor default is 25 and the prefab may override it.
     `m_perfectBlockStaminaDrain` is public.
7. **Success.** `AddStaggerDamage` measures whether the guard broke. `ok = HaveStamina(0) && !guardBroken` (V_12). If ok:
   `hit.m_statusEffectHash = 0`, `hit.BlockDamage(blocked)`, and the "blocked" damage text shows.
8. **Durability.** Shield durability `-= m_useDurabilityDrain * (blockable / blockPower) * Game.m_durabilityRate`.
9. **Skill and effects.** `RaiseSkill(Blocking, parry ? 2 : 1)` (IL_01ff), then the `m_blockEffect` EffectList.
10. **Normal block with an attacker:** `AddAdrenaline(m_blockAdrenaline)`.
11. **Parry with attacker and ok:**
    - `m_perfectBlockEffect`, `AddAdrenaline(m_perfectBlockAdrenaline)`, and the attacker is staggered if
      `m_staggerWhenBlocked`.
    - If the shield's `m_perfectBlockStaminaRegen > 0`, `AddStamina(regen)`. Otherwise a SECOND
      `SEMan.ModifyBlockStaminaUsage` call follows (IL_038c), and stamina is used again.
    - Then the shield's `m_perfectBlockStatusEffect`, or else `Humanoid.m_perfectBlockStatusEffect`, is added
      (IL_03ad-IL_0414).
12. **Pushback.** If ok, `hit.m_pushForce *= fraction`. A melee attacker gets a deflection push hit. The method returns
    true.

**Polling signals.** None are clean:
- There is no PlayerStatType for blocks.
- `m_blockTimer` is private and is not an event.
- Adrenaline only moves with a trinket.
- The Blocking skill accumulator moves +1 or +2, but it is scaled by SE raise modifiers and the SkillGainRate world
  modifier (which the saga writes), and it resets on level-up. Fragile.
- `StatusEffect.ModifyRaiseSkill(Blocking, ref 1f)` fires once per block (Player.RaiseSkill passes 1f, not the value), so
  it cannot tell a parry from a block.

**Hook.** A custom SE subclass on the player, using three virtuals that all run synchronously inside one RPC_Damage:

| Override | When it fires | What it gives |
|---|---|---|
| `OnDamaged(hit, attacker)` | SEMan.OnDamaged at RPC_Damage IL_02c7, before BlockAttack | Arm a "real hit in progress" flag |
| `ModifyBlockStaminaUsage(base, ref use)` | Once per block attempt (IL_012a) | The block event |
| `ModifyTimedBlockBonus(ref bonus)` | Only on a parry attempt (IL_0087), before success is known | The parry event |

- `ModifyBlockStaminaUsage` is also called by the inventory tooltip, `Player.AppendEquipmentModifierTooltips` → 
  `GetEquipmentModifierPlusSE` (54048), with `base = 1`. The armed flag from `OnDamaged` filters that call out.
- In the stamina override, `use *= 0.5f` is the "half the stamina" part. The plain field
  `SE_Stats.m_blockStaminaUseModifier = -0.5f` does the same with no override
  (`use += base * mod; use += m_blockStaminaUseFlatValue`).
- In the parry override, heal 10 there.
- A guard broken mid-parry is the only false positive. If it matters, check `player.IsStaggering()` a frame later.
- `Character.Heal` called from inside the callback is safe: the player is the owner, so it goes straight to RPC_Heal.

**Verdict: existing hook: a mod SE_Stats subclass on the player overriding OnDamaged + ModifyBlockStaminaUsage
+ ModifyTimedBlockBonus; no Patcher change.**

## 3. Per-creature buffs (War Song for player and tames, Forge-skin, Bloodied healing)

**AddStatusEffect overloads** (SEMan, sure):

- `StatusEffect AddStatusEffect(int nameHash, bool resetTime = false, int itemLevel = 0, float skillLevel = 0, short variant = -1)`
  (95466). It works only for ObjectDB effects. When this client is the owner it adds locally (Internal_AddStatusEffect,
  95562); otherwise it sends `RPC_AddStatusEffect` to the owner.
- `StatusEffect AddStatusEffect(StatusEffect se, bool resetTime = false, int itemLevel = 0, float skillLevel = 0, short variant = -1)`
  (95615):
  - If one with the same NameHash is present, it resets the time (when resetTime) and returns null.
  - Otherwise it runs `se.CanAdd(character)` (the base returns true) and `Clone()` (MemberwiseClone, keeping the derived
    type), adds to the list, and calls `Setup(character)` then `SetLevel`.
  - **There is no ownership check and no RPC:** it adds on whatever client calls it.
- `RemoveStatusEffect(int nameHash, bool quiet = false)` (95716); `HaveStatusEffect(int)` (95938);
  `GetStatusEffect(int)` (95978).

**It must run on the creature's owner.** `SEMan.Update` (TTL and ticks) runs only for the owner (Character.CustomFixedUpdate
2323, IL_001b/IL_0063 gate before IL_007e). RPC_Damage and creature attacks also run on the owner. So check
`view.IsOwner()` or `ClaimOwnership()` first, as `ShepherdStar` already does (BoonEffects.cs:1389). Solo this is always the
local client.

**SE_Stats fields** (class at 100468, constructor at about 102855; defaults in brackets):

| Purpose | Field | How it applies | Scope |
|---|---|---|---|
| Outgoing damage | `m_damageModifier` [1], `m_modifyAttackSkill` [None=0], `m_percentigeDamageModifiers` (DamageTypes, [0]) | `ModifyAttack` (101218): if `skill == m_modifyAttackSkill \|\| m_modifyAttackSkill == All(999)`, then `hit.m_damage.Modify(m_damageModifier)`; then always `hit.m_damage.Modify(m_percentigeDamageModifiers)`. For War Song: `m_modifyAttackSkill = Skills.SkillType.All`, `m_damageModifier = 1.25f`. | **Applies to tames** (next paragraph) |
| Incoming, by resistance | `m_mods` (`List<HitData.DamageModPair>`) | `ModifyDamageMods` → `DamageModifiers.Apply`, via `Character.GetDamageModifiers` → `m_seman.ApplyDamageMods` (8828) | **All characters** |
| Incoming, by armour | `m_addArmor`, `m_armorMultiplier` [0] | `ModifyArmorMods`: `armor = (armor + add) * (1 + mult)`, so x1.5 is `m_armorMultiplier = 0.5f` | **Player only** (next paragraph) |
| Health | `m_healthRegenMultiplier` [1] | Called only by Player.UpdateFood (38246) | Player only |
| Health | `m_healthPerTick`, `m_tickInterval` | `Heal(hp, true)` on the owner; ticks only while health% >= `m_healthPerTickMinHealthPercentage`. That field is a floor, so "heal when low" is NOT expressible with it. | Any character |
| Health | `m_healthOverTime`, `m_healthOverTimeDuration`, `m_healthOverTimeInterval` [5] | Heal ticks | Any character |
| Health | `m_healthUpFront` | One-off heal | Any character |
| Stamina | `m_staminaRegenMultiplier` [1] | Called only by Player.UpdateStats | Player only |
| Stamina use | `m_swimStaminaUseModifier`, `m_blockStaminaUseModifier`, `m_attackStaminaUseModifier`, ... | `use += base * mod` | Player paths |
| Speed | `m_speedModifier`, `m_swimSpeedModifier` | `SEMan.ApplyStatusEffectSpeedMods`, called from Character movement (4874, 5062, 6459, ...) | All characters |

- Neither regen multiplier is a flat "+N per second": above 1 each adds `(m - 1)`, at 1 or below it multiplies.
- **Damage modifiers do not stack.** `ShouldOverride` (460988) lets a resistance replace a weakness, but Resistant does
  not override VeryResistant. The factors (459712): SlightlyResistant 0.75, Resistant 0.5, VeryResistant 0.25,
  SlightlyWeak 1.25, Weak 1.5, VeryWeak 2.
- **Why armour is player-only.** It is read only by `Player.GetBodyArmor` → `SEMan.ApplyArmorMods` (53310), and
  RPC_Damage applies body armour only `if (IsPlayer())` (IL_0592). A creature's armour is just
  `Game.m_worldLevel * m_worldLevelEnemyBaseAC`.

**Does ModifyAttack apply to tames? Yes.** Every caller is in `Attack` and passes `m_character.GetSEMan()`, where
m_character is a Humanoid: DoMeleeAttack IL_09e8, checkHits 80018, FireProjectileBurst 76576. There is no IsPlayer gate
(checked around IL_09d9). Creature attacks are Humanoid Attacks run on the creature's owner. So War Song's +25% for both
player and tames is one SE_Stats with `All/1.25` laid on each.

**Forge-skin on a tame, exactly.** `m_mods` only offers steps. A subclass overriding `OnDamaged(HitData hit, Character a)`
can call `hit.ApplyModifier(0.67f)`. That runs on the victim's owner before block, resistance and armour, because
SEMan.OnDamaged is at RPC_Damage IL_02c7. It gives an exact percentage reduction for player or tame. Valheim armour is
not linear (ApplyArmor), so "armour x1.5" and "damage x0.67" are not the same thing; choose one.

**Bloodied healing.** Poll health against a threshold and call `Heal`, or override `UpdateStatusEffect` in a subclass. The
built-in per-tick field cannot do "below X%".

**How the mod does these today.**
- **Runtime effects already exist.** `CreateInstance<SE_Stats>` (HunterHush), `CreateInstance<StatusEffect>`
  (SagaWinds.Make), and `CreateInstance<SE_Puke>` (CheatCommands.cs:1835). All are on the player only.
- **Reckless "you take more" and Blood Rage's cost.** Neither uses an SE. `RefreshDamageModifiers`
  (BoonEffects.cs:1173) rewrites `player.m_damageModifiers` from a pristine snapshot. Holding "reckless" or "rage" sets
  blunt/slash/pierce to `Weak` (x1.5), or to Normal where a resistance boon also claims the slot (1216-1221).
- **Shield Wall ("bulwark").** The same struct: `RaiseToResistant` on blunt, slash and pierce for 20 s
  (ActivateBulwark, 2307).
- **Outgoing damage (Sharpened, Glass Cannon, Blood Rage x1.5, War Song x1.15).** It scales the equipped weapons'
  shared `m_damages` (per prefab) by the product of live multipliers (`RefreshWeaponDamage`, 1092). Player only. War Song
  explicitly does not reach tames (comment at 2552).
- **Gear durability.** No saga boon touches it; only the GM CheatCommands (1378-1460) and the repair loops do.

**Verdict: existing hook: runtime SE_Stats (or a subclass) via SEMan.AddStatusEffect(StatusEffect) on each
creature's owner. ModifyAttack and m_mods work on tames; armour and regen multipliers are player-only. No Patcher change.**

## 4. The ballista (Smiðr's Watch-post)

**Prefabs.** From docs/catalog/game-catalog.md:1042-1044:

| Prefab | Name | Allowed ammo |
|---|---|---|
| `piece_turret` | Ballista | TurretBolt (Black Metal Missile), TurretBoltWood (Wooden Missile), TurretBoltFlametal, TurretBoltBloodgold |
| `fuling_turret` | Ballista | TurretBolt, TurretBoltWood |
| `piece_Charred_Balista` | Skugg | TurretBoltBone |

The bone, iron and black-metal bolts the plan names (`BoltBone`, `BoltIron`, `BoltBlackmetal`, also `BoltCarapace`,
`BoltCharred`, `BoltBloodGold`, catalog 2203-2208) are **crossbow** ammo and are NOT in the ballista's allowed list.
The bolt rungs therefore map to `TurretBoltWood`, then `TurretBolt` (black metal), then `TurretBoltFlametal` or
`TurretBoltBloodgold`.

**Class Turret** (517310-520101). All fields below are public instance fields, so they are settable per instance after
Instantiate:
- `m_maxAmmo` (int), `m_defaultAmmo` (ItemDrop), `m_ammoType` (string, constructor default "$ammo_turretbolt").
- `m_allowedAmmo` (`List<Turret.AmmoType>`, each with `{ItemDrop m_ammo, GameObject m_visual}`).
- `m_returnAmmoOnDestroy` [true].
- `m_targetPlayers` [true], `m_targetTamed` [true], `m_targetEnemies` [true], `m_targetTamedConfig`.
- `m_viewDistance` [10], `m_horizontalAngle` [25], `m_attackCooldown` [1], `m_updateTargetIntervalNear/Far` [1/10].

The constructor defaults are in brackets; the prefab overrides them.

**Targeting.** `FixedUpdate` runs `UpdateTarget` and `UpdateAttack` **only on the ZDO owner**; other clients only
`ReadTargets`. `UpdateTarget` (needs `HasAmmo()`) calls

```
BaseAI.FindClosestCreature(transform, eye.position, 0f, m_viewDistance, m_horizontalAngle,
    alerted:false, mistVision:false, passiveAggresive:true, includePlayers:m_targetPlayers,
    includeTamed: m_targetItems.Count > 0 ? m_targetTamedConfig : m_targetTamed,
    includeEnemies:m_targetEnemies, onlyTargets:m_targetCharacters)
```

`FindClosestCreature` (89661) uses **no faction and no `IsEnemy`**:
- It skips players unless includePlayers, skips every non-player unless includeEnemies, and skips tamed unless
  includeTamed.
- When the trophy list is non-empty it skips anything whose `m_name` is not on it.
- It skips dead and sleeping creatures, requires `BaseAI.CanSenseTarget`, and picks the closest.

So with `m_targetEnemies` it shoots **every awake, untamed non-player it can see, deer included**. Set
`m_targetPlayers = false` and `m_targetTamed = false` on the instance, because both default to true. **No creator, Piece
setting or PrivateArea is needed.** The turret is created locally, so it is owned locally and its targeting runs. Sure.

**Ammo.** The ZDO vars are set in ZDOVars' static constructor (281475-281873):

| Var | Key | Type | Used by |
|---|---|---|---|
| `ZDOVars.s_ammo` | "ammo" | int | GetAmmo, RPC_AddAmmo, ShootProjectile |
| `ZDOVars.s_ammoType` | "ammoType" | string (prefab name) | GetAmmoType, when `m_defaultAmmo` is null |
| `ZDOVars.s_lastAttack` | "lastAttack" | float, ZNet time | the cooldown |
| `ZDOVars.s_targets` | "targets" | | trophy config |

- `HasAmmo()` is `m_maxAmmo == 0 ? true : GetAmmo() > 0`.
- `GetAmmoType()` is `m_defaultAmmo ? m_defaultAmmo.name : zdo.GetString(s_ammoType, "")`.
- `GetAmmoItem()` resolves `ZNetScene.GetPrefab(type)`. If that is null it logs a warning and returns null, and
  `ShootProjectile` then dereferences null.

Two ways to load it:

1. **Infinite, the cheapest:** `turret.m_maxAmmo = 0; turret.m_defaultAmmo = scene.GetPrefab("TurretBolt").GetComponent<ItemDrop>();`.
   It never decrements (ShootProjectile only writes s_ammo when `m_maxAmmo > 0`) and fires one projectile per shot.
2. **Finite:** as owner, `zdo.Set(ZDOVars.s_ammo, n)` and `zdo.Set(ZDOVars.s_ammoType, "TurretBolt")`. Or call
   `RPC_AddAmmo(name)` once per bolt; it checks `IsItemAllowed`, which the ZDO write bypasses.

**Projectile.** `ShootProjectile` calls `IProjectile.Setup(owner: null, ...)` (IL_0335). Three consequences:
- Bolts have **no attacker**. They do not tick EnemyHits and kills are not credited to the player. Kill challenges still
  count: `RunService.OnCharacterDied` → `ReportKill` does not check the attacker.
- With a null owner, `Projectile.IsValidTarget` (81683) treats **every** Character as valid, so a stray bolt can hit the
  player or a tame (vanilla behaviour).
- `HitData.m_pushForce` comes from the ammo's `m_attackForce`.

**Persistence.**
- Instantiate, then `zdo.Persistent = false`, the same pattern as `RaiseStation` (BoonEffects.cs:3020-3062).
- Save skips it: `ZDOMan.AddObjectsPerChunk` IL_00b4 checks `get_Persistent` and skips non-persistent ZDOs (277609).
- `ZNetScene.RemoveObjects` (294388; IL_00ee-IL_0107 at about 294500) destroys a non-persistent ZDO the client owns when
  it goes out of range. So it vanishes when the player walks off; it is never saved. Sure.

Take the Field Forge's precautions, and one more for the ballista. Otherwise a broken turret drops BlackMetal x10,
YggdrasilWood x10 and MechanicalSpring x3, plus its ammo:
- `piece.m_canBeRemoved = false` and `piece.m_resources = new Piece.Requirement[0]`.
- `turret.m_returnAmmoOnDestroy = false`. Turret.OnDestroyed (via WearNTear.m_onDestroyed) drops GetAmmo() items.

Take it down with `DestroyByZdo`.

**Verdict: no hook needed. Instantiate piece_turret, set the per-instance flags and m_defaultAmmo/m_maxAmmo (or the
s_ammo/s_ammoType ZDO), make the ZDO non-persistent; no Patcher change.**

## 5. Area effects for the Sæfari's Undertow (stagger, knockback, Wet within 6 m)

**Existing methods** (BoonEffects.cs):

| Method | What it does |
|---|---|
| `ActivateWarcry()` (1960) | `HostilesNear(player.pos, WarcryRadius=8, player, skipBosses:true)`, then `c.Stagger(AwayFrom(from, c))` per foe |
| `ActivateRend()` (1912) | `HostilesNear(pos, RendRadius=5, ..., skipBosses:false)`; per foe a `new HitData{ m_slash = 20*scale, m_poison = 15*scale }`, then `AimHit` and `DamageOne`. The poison becomes the game's SE_Poison bleed. |
| `HostilesNear(Vector3, float, Player, bool)` (2098) | `Character.GetCharactersInRange`; drops players, tamed and dead (and bosses when asked) |
| `AimHit(HitData, Character, Vector3, Player)` (2116) | Sets m_point, m_dir (away from the source) and `SetAttacker(player)` |
| `DamageOne(Character, HitData, string)` (2132) | `c.Damage(hit)` in a try |
| `ClassDamageScale()` | The per-boss scaling |

**Stagger.** `Character.Stagger(Vector3)` (9690, public) calls `RPC_Stagger` directly when owner, otherwise sends it to
the owner. Alternatively, `HitData.m_staggerMultiplier >= 100` forces `Stagger(hit.m_dir)` inside RPC_Damage
(IL_009f-IL_00b3, skipped only if dead, in a cutscene or teleporting), even for a zero-damage hit.

**Knockback.** `HitData.m_pushForce`. RPC_Damage IL_0452 calls the private `ApplyPushback(HitData)`, which calls the
public `ApplyPushback(Vector3 dir, float pushForce)` (6900):
- The force is `pushForce * Clamp01(1 + GetEquipmentMovementModifier()) / rigidbody.mass * 2.5`, along the hit
  direction (m_dir) with y zeroed.
- It is stored in `m_pushForce` only if larger than the current one, so heavier creatures move less.
- It is applied before the 0.1-damage early-out, so a hit with zero damage still pushes.
- A blocking target scales it by its block fraction.

Sending it through HitData runs it on the owner, which is correct for physics.

**Wet.** The hash is `SEMan.s_statusEffectWet`, `"Wet".GetStableHashCode()` (SEMan static constructor, 97045). The prefab
is SE_Wet (`SE_Stats` subclass, 102890; catalog 4448: "Lowers your health and stamina regeneration", ttl 120). Two ways:
- `c.GetSEMan().AddStatusEffect(SEMan.s_statusEffectWet, resetTime: true)`. The hash overload goes to the owner by RPC.
  The game itself does this for creatures in water (Character.UpdateWater, 12343).
- Or carry it on the hit: `hit.m_statusEffectHash = SEMan.s_statusEffectWet`. RPC_Damage IL_0457-IL_0513 adds it on the
  owner. Immunity is checked only for Burning, Frost, Lightning and Poison. A HitData carries one status effect.

What Wet does to a creature (sure; prefab values unknown):
- SE_Wet.UpdateStatusEffect deals `m_waterDamage` every `m_damageInterval` to creatures without `m_tolerateWater`.
- It shortens Burning.
- The regen penalties are player-only, as in section 3.

**Cheapest Undertow.** One HitData per foe, through `DamageOne`:
- `m_pushForce = N`, `m_staggerMultiplier = 100` (forced stagger; Warcry's manual skip-bosses filter still applies).
- `m_statusEffectHash = SEMan.s_statusEffectWet`, optionally a little damage, and `AimHit` for direction and attacker.

Everything then runs on the owner in one RPC. As with Rend, each target adds to EnemyHits (section 1).

**Verdict: no hook needed. Reuse HostilesNear, AimHit and DamageOne with a HitData carrying m_pushForce,
m_staggerMultiplier >= 100 and m_statusEffectHash = SEMan.s_statusEffectWet (or Stagger() plus
AddStatusEffect(s_statusEffectWet)); no Patcher change.**

## 6. The Ward pulse on land

`SeaWatch.Pulse(Player, SeaSettings)` (SeaWatch.cs:137-157):

```csharp
if (s.WardTier < 1 || Time.time < _nextPulse) return;
var ship = Ship.GetLocalShip();
if (ship == null) return;                                   // the only "aboard" gate
...
Character.GetCharactersInRange(ship.transform.position, ShipFittings.WardRadius(s.WardTier), _inRange);
```

- `Ship.GetLocalShip()` returns the last of `Ship.s_currentShips`, the ships whose trigger the local player is inside,
  or null.
- `StrikeOne` already centres nothing: it strikes `c.GetCenterPoint()` with attacker = player, filtered by
  `ShipFittings.WardStrikes` (alerted, hostile MonsterAI only).
- `Tick` calls `Pulse` every poll second whenever a run is live (`RunService.PollSea`, RunService.cs:2747/7116), before
  the sea-danger gating. A land pulse therefore needs no new tick.

To change:
1. Add a flag to `SeaSettings`, for example `bool WardOnFoot`. Set it in `RunService.SeaSettingsNow()`
   (RunService.cs:7097-7105) from "the Sæfari's engine is held".
2. In `Pulse`, replace the null-ship return with
   `Vector3 centre; if (ship != null) centre = ship.transform.position; else if (s.WardOnFoot) centre = player.transform.position; else return;`
   and pass `centre` to `GetCharactersInRange`.
3. `WardTier` is `_fittings.Ward`, which is per run, not per ship. A Sæfari who never bought a ward has tier 0, so the

4. Update the text that says "aboard": `ShipFittings.Summary` (ShipFittings.cs:171) and the doc comments.

**Verdict: no hook needed. A centre fallback to player.transform.position behind a new SeaSettings flag, plus a

## 7. Swim stamina (Tide-borne made permanent)

**Today.** `ActivateTide()` (BoonEffects.cs:2646) lends `+8` to `Player.m_staminaRegen` (field loan "tide",
`LendField(player, "StaminaRegen", "tide", 8f)`) for 30 s, and `EndTide` (2678) repays it. The doc comment claims
"Swimming and rowing drain less than that, so for the window the water cannot tire you."

**The IL contradicts that comment.** In `Player.UpdateStats(float)` (36771), IL_0051-IL_007e set the regen multiplier V_2
to **0** whenever `IsSwimming() && !IsOnGround()` (also during attack, dodge, wall-running or encumbrance). So
`m_staminaRegen` does nothing while swimming. Tide-borne's +8 never offsets the swim drain, and a swimming player still
tires. (Valheim's oars use no stamina, so the "rowing" half is moot.) Sure. This is a doc/code mismatch worth logging.

**The swim drain.** `Player.OnSwimming(Vector3, float)` (38899) computes
`use = Lerp(m_swimStaminaDrainMinSkill, m_swimStaminaDrainMaxSkill, swimSkillFactor) * (1 + equipSwimMod)`, then
`SEMan.ModifySwimStaminaUsage(use, ref use, minZero: true)`, then `UseStamina(dt * use * Game.m_moveStaminaRate)`.
It drowns (MaxHealth/20 per second) only when `!HaveStamina(0)`.

**The cheap always-on fix.** An `SE_Stats` with `m_swimStaminaUseModifier = -1f`. `SE_Stats.ModifySwimStaminaUsage` does
`use += base * mod`, which is 0, and `minZero` clamps it. Lay it on the player as HunterHush is laid, and reapply it in
`ReapplyPassiveBoonEffects` (RunService.cs:3954), because death clears effects.
- Alternatively, two field loans set `Player.m_swimStaminaDrainMinSkill` and `m_swimStaminaDrainMaxSkill` to 0. That
  needs new `FieldAccess` entries (BoonEffects.cs:341).
- Either way, entering the water at exactly 0 stamina would still drown. Optionally top up stamina while swimming.

**Verdict: no hook needed. A permanent SE_Stats with m_swimStaminaUseModifier = -1 (SEMan.ModifySwimStaminaUsage
in Player.OnSwimming). The current +StaminaRegen loan cannot do it, because regen is zeroed while swimming.**

## 8. Health regen for allies (Völva's Hearthlight)

**Signature.** `public void Character.Heal(float hp, bool showText = true)` (decl. at 7750, ends 7790):
- `hp <= 0` returns.
- If `m_nview.IsOwner()` it calls `RPC_Heal(0, hp, showText)` directly; otherwise
  `m_nview.InvokeRPC("RPC_Heal", hp, showText)` routes to the owner.
- `RPC_Heal` (7794) runs only on the owner and only if health > 0 and not dead. It does
  `SetHealth(Min(health + hp, max))` and shows green text if showText.

So it **works on tames from any client**; ownership is handled by the RPC. Sure.

**Today.** `RefreshHearthlight(bool held)` (BoonEffects.cs:1326) runs every 5 s: `player.Heal(4f)`, plus `c.Heal(8f)` for
every tamed non-player in `GetCharactersInRange(player.pos, 15f)`.

**For 3/s.**
- Either `Heal(15f)` every 5 s, or `Heal(3f, false)` every second. `showText:false` avoids a number every second.
- Or lay an SE_Stats with `m_tickInterval = 1, m_healthPerTick = 3` on each ally (it ticks on the owner). Its Heal
  hard-codes `showText = true` (IL_0070), so it spams numbers.

**Verdict: no hook needed. Poll and call Character.Heal(float, bool), which already routes to the owner.**
